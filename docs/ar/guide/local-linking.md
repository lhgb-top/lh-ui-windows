# الربط المحلي

## اصطلاح تخطيط العائلة

```
lh-ui/                        # الدليل الأب للعائلة (وليس مستودعًا)
├── lh-ui-core/               # المصدر الأصلي للرموز + codegen
├── lh-ui-android/            # مستودعات شقيقة
├── lh-ui-ios/
├── lh-ui-harmony/
└── lh-ui-windows/            # هذا المستودع
```

عندما تتواجد المستودعات تحت والدلة واحدة، تُربط الرموز **محليًا مباشرة**؛ وعند غياب المستودعات الشقيقة (استنساخ مستودع واحد في CI) **يُرتد تلقائيًا إلى حزمة npm**.
وهذا يتسق مع آلية حارس vite alias في سلالة الويب (الخطة الرئيسية D18).

## حارس من ثلاث مستويات

يبحث `scripts/link-tokens.mjs` عن منتجات الرموز حسب الأولوية:

| الأولوية | المصدر | الشرح |
| --- | --- | --- |
| 1 | `../lh-ui-core/dist/windows` | ربط محلي مباشر: تغيير الرموز يسري فورًا |
| 2 | `node_modules/@lh-ui/core/dist/windows` | ارتداد npm: يحتوي `files:["dist"]` لحزمة `@lh-ui/core` على منتجات كل طرف |
| 3 | — | الخروج بخطأ، فبدون الرموز لا يمكن البناء |

موقع سقوط الرموز هو `src/Tokens/` (قيمة `relativePath` في codegen هي `Tokens/*.cs`)، ويشير
`using Top.Lhgb.Ui.Tokens;` من جانب المكوّنات إلى هذا الموقع. هذا الدليل منتجات مولّدة (`.gitignore`)، ويُمنع التعديل اليدوي.

## سير العمل اليومي

```bash
# 1. تعديل الرموز (في مستودع core)
cd ../lh-ui-core
vim tokens/color.json           # أو spacing / typography / ...

# 2. إعادة التوليد + التحقق
pnpm codegen                    # توليد منتجات dist/ لكل طرف
pnpm verify                     # schema + المراجع + تباين WCAG + اتساق العقود

# 3. العودة إلى هذا المستودع للمزامنة
cd ../lh-ui-windows
pnpm link:tokens                # استبدال src/Tokens/

# 4. الانحدار (dotnet)
dotnet test                     # حالات xUnit الذهبية
dotnet build                    # الترجمة هي نفسها فحص الأنواع
```

## رموز موقع التوثيق

يتم توليد متغيرات CSS لمحاكي موقع التوثيق من الرموز أيضًا:

```bash
pnpm gen:sim                    # توليد docs/.vitepress/theme/sim-tokens.css
pnpm docs:dev                   # يشغّل gen:sim داخليًا أولًا، المنفذ 5186
pnpm sim:check                  # التحقق من عدم وجود قيم رموز حرفية في CSS الخاص بالمحاكي (خط أحمر)
```

## بوابة CI

```bash
pnpm link:tokens:check          # كشف ما إذا كانت الرموز قد تمت مزامنتها (مقارنة عدد الملفات، وعند عدم المزامنة يكون رمز الخروج 1)
```

## ممنوعات

- ❌ التعديل اليدوي على `src/Tokens/` (منتجات مولّدة، مُتجاهَلة في gitignore)
- ❌ إيداع ملفات الرموز المولّدة في المستودع
- ❌ كتابة قيم حرفية للألوان/المسافات داخل المكوّنات (مثل `Color.FromArgb(0xFF,0x2B,0x4C,0x7C)`، `new GridLength(40)`، أرقام حجم الخط)
- ❌ تجاوز `link:tokens` ونسخ المنتجات يدويًا

## تشخيص الأعطال

| العَرَض | السبب | الحل |
| --- | --- | --- |
| خطأ ترجمة `The type or namespace 'LhTokens' does not exist` | الرموز غير مزامَنة | `pnpm link:tokens` |
| قيم الرموز غير مطابقة للتوقع | لم يُعَد توليد codegen في مستودع core | أعد `pnpm codegen` في مستودع core ثم أعد الربط |
| يُبلغ `link:tokens` عن «لم تُوجد منتجات الرموز» | المستودعات الشقيقة غير موجودة ولم تُثبَّت حزمة npm | تحقق من تخطيط العائلة أو `pnpm i -D @lh-ui/core` |
| ألوان الوضع الداكن غير صحيحة | تم تغيير اللون الرئيسي الفاتح دون تحديث الحساب المسبق للداكن | حدّث `color-dark.json` وأعد التشغيل (R-n6) |
| ألوان المكوّنات فاتحة جميعها | نقطة الدخول لم تستدعِ `LhTheme.Apply` | استدعِها مرة عند بدء تشغيل App / النافذة الرئيسية |
| يُبلغ `dotnet build` عن أخطاء XAML مثل `MC1000` | تبني المكوّنات شجرة بصرية برمجيًا، ولا يوجد XAML في المستودع | تحقق من إضافة ملف `.xaml` بالخطأ |
