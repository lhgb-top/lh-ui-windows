# Локальная линковка

## Соглашение о семейной раскладке

```
lh-ui/                        # родительский каталог семейства (не репозиторий)
├── lh-ui-core/               # единый источник токенов + codegen
├── lh-ui-android/            # родственные репозитории
├── lh-ui-ios/
├── lh-ui-harmony/
└── lh-ui-windows/            # этот репозиторий
```

Когда все репозитории лежат в одном родительском каталоге, токены подключаются **напрямую локально**; если родственных репозиториев нет (одиночный clone в CI), выполняется **автоматический fallback на npm-пакет**.
Это структурно аналогично механизму защиты vite alias в направлении web (генеральный план, D18).

## Трёхуровневая защита

`scripts/link-tokens.mjs` ищет артефакты токенов в порядке приоритета:

| Приоритет | Источник | Описание |
| --- | --- | --- |
| 1 | `../lh-ui-core/dist/windows` | Локальное подключение: изменение токенов применяется мгновенно |
| 2 | `node_modules/@lh-ui/core/dist/windows` | npm-fallback: `files: ["dist"]` в `@lh-ui/core` содержит артефакты всех сторон |
| 3 | — | Ошибка с выходом: без токенов сборка невозможна |

Токены попадают в `src/Tokens/` (`relativePath` codegen — `Tokens/*.cs`); сторона компонентов
`using Top.Lhgb.Ui.Tokens;` указывает именно туда. Каталог является генерируемым (`.gitignore`), ручное редактирование запрещено.

## Ежедневный цикл

```bash
# 1. Изменить токены (в репозитории core)
cd ../lh-ui-core
vim tokens/color.json           # или spacing / typography / ...

# 2. Перегенерировать + проверить
pnpm codegen                    # сгенерировать артефакты dist/ для всех сторон
pnpm verify                     # schema + ссылки + контрастность WCAG + согласованность контрактов

# 3. Вернуться в этот репозиторий и синхронизировать
cd ../lh-ui-windows
pnpm link:tokens                # перезаписать src/Tokens/

# 4. Регрессия (dotnet)
dotnet test                     # золотые сценарии xUnit
dotnet build                    # сборка с проверкой типов
```

## Токены сайта документации

CSS-переменные симулятора сайта документации также генерируются из токенов:

```bash
pnpm gen:sim                    # сгенерировать docs/.vitepress/theme/sim-tokens.css
pnpm docs:dev                   # внутри сначала запускается gen:sim, порт 5186
pnpm sim:check                  # проверить, что в CSS симулятора нет литералов токенов (красная линия)
```

## CI-гейт

```bash
pnpm link:tokens:check          # проверить, синхронизированы ли токены (сравнение количества файлов; если нет — код выхода 1)
```

## Запрещено

- ❌ Ручное редактирование `src/Tokens/` (генерируемое содержимое, gitignore)
- ❌ Коммит сгенерированных файлов токенов в репозиторий
- ❌ Цветовые/размерные литералы в компонентах (например `Color.FromArgb(0xFF,0x2B,0x4C,0x7C)`, `new GridLength(40)`, числовые размеры шрифта)
- ❌ Ручное копирование артефактов в обход `link:tokens`

## Диагностика

| Симптом | Причина | Решение |
| --- | --- | --- |
| При компиляции `The type or namespace 'LhTokens' does not exist` | Токены не синхронизированы | `pnpm link:tokens` |
| Значения токенов не соответствуют ожиданиям | В репозитории core не перезапущен codegen | `pnpm codegen` в core, затем повторить link |
| `link:tokens` сообщает «артефакты токенов не найдены» | Родственных репозиториев нет, npm-пакет не установлен | Проверить семейную раскладку или `pnpm i -D @lh-ui/core` |
| Тёмные цвета неверны | Изменили светлый основной цвет, но не обновили предвычисление тёмной темы | Обновить `color-dark.json` и перезапустить (R-n6) |
| Все цвета компонентов светлые | Во входной точке не вызван `LhTheme.Apply` | Вызвать один раз при запуске App / главного окна |
| `dotnet build` сообщает об ошибках XAML (`MC1000` и др.) | Компоненты строят визуальное дерево кодом, XAML в репозитории нет | Проверить, не добавлен ли случайно файл `.xaml` |
